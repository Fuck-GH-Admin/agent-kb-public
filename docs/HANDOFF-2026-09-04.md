## 1. 本轮最后留下的未提交代码

提交前只有两个代码文件有未提交变更：

### `kb/util.py`

修复 `read_text` 的大文件多字节编码边界问题：

- 旧实现按字节读取后直接 `raw.decode()`；如果 GBK/UTF-8 字符被截断，解码失败，
  可能错误回退到 UTF-8 replacement，导致整段文本乱码。
- 新实现使用 incremental decoder，并在已截断的预览上使用 `final=False`。
- 这是由真实数据复现的：`/home/miku/Bot/novel/围城.txt` 是 GBK/扩展 ASCII 风格，
  旧摘要/块里搜索不到“方鸿渐”。
- **重要：代码修复后，旧生产条目不会自动改变。** 下次必须对受影响源文件强制重摄取。

### `kb/ingest.py`

块指纹新增 `text_len`：

- 指纹现在包含 `size / overlap / content_hash / text_len`。
- 解决“文件 hash 没变，但文本抽取/解码逻辑修复了”的旧块不会重建问题。
- 这也是为什么下次重摄取应使用 `--force-hash`，让新抽取文本进入父条目和块。

## 3. 已完成能力

### 存储与可靠性

- SQLite WAL + FTS5 外部内容表；SHA-256 内容寻址 blob；numpy float32 memmap 分片。
- schema v4：collection/status/origin/visibility/mtime/parent_id/chunk_no。
- 版本化更新、内容去重、原子 blob 写入、verify、doctor、审计日志、trash 回收站。
- `restore` 已真实演练；曾抓到 WAL 写回导致恢复静默撤销的 bug，已修复并记录。
- 写者级 `flock`，且是实例级可重入锁；并发 add 实测一方成功、一方清晰拒绝，库一致。
- 备份：`backup --verify --retention N`；恢复：`restore <dir> --yes`；迁移：export/import。

### 检索与内容治理

- BM25F 列加权 + hash/API/local 三种 embedder + RRF 融合。
- 过滤下推到向量候选集，避免小 collection 的召回黑洞。
- FTS 失败时 LIKE 扫描；embedder 不可用时仅关键词；每次返回 warning/degraded。
- CJK 原文 snippet；块命中返回 parent_id/chunk_no 并压制父条目重复结果。
- collection 主题分区、tag 标签、status 审核队列、origin human/agent、visibility
  public/internal/private。
- MCP 默认只读；写入显式 `KB_ALLOW_WRITE=1`，agent 写入默认 pending。
- MCP 写路径白名单：`access.write_roots=[]` 时默认只允许 `$HOME` 下非隐藏路径；
  realpath 后判断，挡 `..` 与软链接穿越。

### 多类型数据

- text/code：文本和代码；代码摘要抽函数/类签名。
- `.ts` 等歧义扩展名：内容嗅探后识别为 code，不误判为 MPEG-TS video。
- Office/ODF：docx/xlsx/pptx/odt 等 zip 容器抽 XML 正文。
- ipynb：只抽 markdown+code，不把 base64 输出灌进索引。
- model：safetensors/gguf/pt/onnx 等只读头部元数据，绝不加载权重本体；legacy
  pickle 摘要带“反序列化可执行任意代码”警告。
- image：尺寸/EXIF；audio/video：ffprobe 元数据；PDF：pypdf/pdftotext 前 8 页。
- git：默认排除 `.git` 目录，工作区代码正常摄取。
- archive/unknown binary：仅元数据，不自动解包，防 zip 炸弹和递归摄取。

### 运维与接入

- `kb watch --once` 可挂 cron/systemd；`--link` 硬链接；大体积复制警告；trash 老化。
- `kb curate` 离线整理，`--ai --apply` 可接 LLM；`kb eval` 计算 recall@k/MRR；
  `kb eval --from-log` 从真实 search→get 行为沉淀金标；`kb gaps` 产出知识缺口。
- `kb drill` 临时库执行备份→破坏→恢复→校验。
- `kb serve-web` 纯标准库面板；MCP stdio；SSH 远程 MCP。
- `deploy/` 有 backup/verify/watch systemd unit、timer 与灾备 runbook。

## 6. 已知设计边界（不要误报成 bug）

- hash embedder 是字符特征相似度，不是真正语义理解；语义质量需要 API 或本地模型并执行
  `kb reembed`。没有 embedding 后端时，FTS 仍应可工作。
- 向量路默认返回最近邻，结果非空不代表命中；agent 必须看 `fts_rank`、`vec_sim`、
  `snippet`，必要时 `kb_get` 复核。
- archive 不自动解包是安全选择，不是缺功能；需检索内部资料时先人工解包/筛选再 add。
- model 不加载权重是安全和资源选择；模型“能否运行”不属于知识库职责。
- `--link` 不是不可变副本：源文件被原地修改会改变 blob inode 内容；需要不可变性时用
  默认 copy，或后续 `verify`/`--force-hash` 检查。
- 多机只读应分发 `kb backup` 快照，不 rsync 活动中的 `kb.db + WAL`。
- 默认 `$HOME` 白名单是用户本轮明确选择的折中；若无法保持 home 整洁或权限边界不清，
  应改为空白 `access.write_roots`，让 agent 只能写 note、不能 add 文件。
